## Brand Strategist

### รอบ 1

- **Positioning ชัดครึ่งเดียว** — headline เดิมยาวและพูด 3 เรื่อง (ครบ · เร็ว/ใช้ง่าย · ส่งต่อได้) คนอ่านไม่รู้ว่าให้จำอะไร จุดต่างจริงคือ **"ทีมรับช่วงต่อได้"** แต่ถูกวางไว้ท้ายประโยค
- เสนอแยก headline (เป็นใคร/ให้อะไร) กับ tagline (ต่างยังไง):
  - Headline: "Full-stack Developer ที่ทำเว็บให้ทีมรับช่วงต่อได้"
  - Tagline: "เร็ว ใช้ง่าย ดูแลต่อได้ — และกำลังทดลองใช้ AI agents ให้งานเว็บดีขึ้น"
- **Audience หลัก = บริษัทที่หาคนร่วมทีม** เพราะ "รับช่วงต่อได้" พูดกับคนจ้างระยะยาว · ฟรีแลนซ์ขาดหลักฐาน (ห้ามโชว์เรท/ลูกค้า) · นักเรียน/เพื่อน dev ดูแลผ่าน Interests
- 3 ข้อเสนอ: (1) ตัด "หลายปี" ใช้หลักฐานที่พิสูจน์ได้ เช่น Lighthouse ของเว็บนี้ (2) Bio เปิดด้วยคุณค่า ไม่ใช่คำทักทาย (3) CTA เดียวแต่เจาะจงขึ้น "คุยเรื่องทีมหรือโปรเจกต์"
- จุดยืนแข็ง: ไม่เอาทางเข้าตาม Audience บน Home ("3 ปุ่ม = ไม่เลือก") · AI agents ใน tagline ด้วยคำ "กำลังทดลอง" · Lighthouse เป็นหลักฐานชิ้นเดียวที่ไม่ละเมิด Do not show

### รอบ 2

- **ยืน:** ไม่มีชิป 3 อันน้ำหนักเท่ากันบน Home · "ทีมรับช่วงต่อได้" ยังเป็นแกน headline — แต่ยอมว่าต้องมีหลักฐาน (ลิงก์ GitHub สาธารณะของโค้ดเว็บนี้) ถ้าไม่มีก่อน ship ให้ถอยเหลือ tagline
- **ยอม:** ย้าย AI agents ออกจาก tagline ไป Interests/About (tagline ควรมีคำสัญญาเดียว) · เอา Lighthouse ออกจากข้อความหลักจนกว่าจะมีตัวเลขพร้อมวันที่/เงื่อนไข · ฟรีแลนซ์ไม่ใช่ audience ระดับ Home · การแยกหัวข้อไปอยู่ที่ dropdown ของ Contact (รับข้อเสนอ UX)
- ประนีประนอม: Home = ปุ่มหลัก 1 + ลิงก์ข้อความรองไป Interests · **gate การเคลม**: ทุกข้อความที่เป็นการเคลมต้องมีหลักฐานบนหน้า ไม่มีหลักฐาน = ตัด
- ฉบับสุดท้าย: Headline **"Full-stack Developer ที่ทำเว็บให้ทีมรับช่วงต่อได้"** · Tagline **"หน้าบ้านถึงหลังบ้าน — โหลดเร็ว ใช้ง่าย โค้ดอ่านออก"** · ใน Interests: "กำลังทดลองใช้ AI agents ให้งานเว็บเร็วและดีขึ้น"

## UX Critic

### รอบ 1

- **ข้อมูลพร้อมไหม:** Home พร้อม (Name + Headline) แต่ไม่มีข้อความ CTA · About **ไม่พร้อม** — `loadProfile()` ใช้ `$` กับ flag `m` เลยหยุดที่ท้ายบรรทัดแรก Bio เหลือย่อหน้าเดียว (L2) · Interests **ไม่พร้อม** — bug เดียวกันเหลือ 1 ข้อ และ `string[]` ไม่มีที่ใส่ "ทำไม" · Contact **ไม่พร้อม** — `Profile` ไม่มีฟิลด์ contact, github/linkedin ว่าง, email เป็น demo
- **จุดสับสน:** CTA เดียว "ทักมาคุยกัน" ไม่บอกว่าทักเรื่องอะไร · ฟรีแลนซ์ไม่มีหลักฐาน · ฟอร์มที่ได้ 501 แล้วขึ้น error = เว็บของคนทำ UX ดูพัง · ไม่มีรูป/บริษัท ความน่าเชื่อถือต้องมาจาก GitHub ที่ยังว่าง · Guestbook ใน nav ดึงความสนใจ
- **IA:** nav 4 ข้อ (หน้าแรก · เกี่ยวกับผม · สิ่งที่สนใจ · ติดต่อ) · Home มีชิป 3 อัน "หาคนร่วมทีม / จ้างทำเว็บ / อยากเริ่มเรียน" → `/contact?topic=` · Interests การ์ด ชื่อ + ทำไม + "คุยเรื่องนี้ →" · Contact: email `mailto:` อยู่**เหนือ**ฟอร์ม, dropdown หัวข้อ, ปุ่ม "ส่งข้อความ" · 501 → "ระบบฟอร์มยังไม่เปิดใช้ — ส่งอีเมลมาที่ … ได้เลยครับ" และไม่ลบข้อความที่พิมพ์ไว้ · ฟิลด์ contact ว่างให้ซ่อน
- จุดยืนแข็ง: ทางเข้าตาม Audience ต้องเป็น Must · Contact ต้องใช้ได้ 100% แม้ 501 (ไม่งั้นซ่อนฟอร์ม) · Interests ต้องมี "ทำไม" ไม่งั้นรวมเข้ากับ About

### รอบ 2

- **ยอม (ต่อ Brand):** Home ปุ่มหลักปุ่มเดียว เอาชิปออก
- **ยืน:** ผู้ใช้ต้องรู้ว่าทักเรื่องอะไรได้บ้าง → ประนีประนอม: บรรทัดเล็กใต้ปุ่มเป็นข้อความธรรมดา + dropdown หัวข้อที่ Contact
- **ยอม (ต่อ Devil):** ฟอร์มเป็น Nice · Must = `mailto:` อีเมลจริง · Guestbook ไม่ลิงก์ทั้ง nav และ footer จนกว่าจะปลอดภัย
- **ยืน:** Contact ต้อง "ไม่มีทางตัน" — ทุกสถานะมีช่องทางติดต่อที่ใช้ได้ · ห้ามโชว์ `err.message` · ถ้ายังเป็น `demo@example.com` หน้า Contact ห้าม ship
- **ยืน:** Interests ต้องมี "ทำไม" — ทำได้โดยไม่แก้ type: เขียน `ชื่อ — เหตุผล` ใน `string[]` เดิม (ต้องแก้ L2 ก่อน) · ถ้าตัดสินเป็น Nice ให้ยุบ Interests เป็น section ใน About
- Microcopy ยืนยัน: ปุ่ม "ทักมาคุยกัน" · ใต้ปุ่ม "รับคุยเรื่องร่วมทีม · โปรเจกต์ · เริ่มเรียนเขียนเว็บ" · หัว Contact "อยากคุยเรื่องอะไร บอกได้เลยครับ" · dropdown "ร่วมทีม / จ้างทำโปรเจกต์ / เรื่องเรียนเขียนเว็บ / อื่น ๆ" · ส่งไม่สำเร็จ "ตอนนี้ส่งผ่านฟอร์มไม่ได้ — ข้อความของคุณยังอยู่ คัดลอกแล้วส่งอีเมลมาที่ [email] ได้เลยครับ"

## Devil's Advocate

### รอบ 1

ความเสี่ยง (มีหลักฐานจากไฟล์):

1. **Guestbook XSS** — `src/pages/guestbook.astro` ใช้ `innerHTML` กับ `e.name`/`e.message` ไม่ escape · `maxlength` มีแค่ฝั่ง client · ตาราง guestbook ไม่มีคอลัมน์ moderate
2. **Spam / DB โต** — POST ไม่มี rate limit/honeypot · GET ดึงทุกแถวไม่มี limit → ช้าและดิสก์เต็ม สวนกับ headline "โหลดเร็ว"
3. **Error รั่ว** — API คืน `{ error: err.message }` และหน้า contact แสดงตรง ๆ → ผู้ชมเห็น `NOT_IMPLEMENTED: … Lab 05 OpenCode` (อ้างคอร์สตอน runtime · test ไม่จับ) · ต่อไปอาจเป็น error SQLite
4. **Contact เก็บ PII ไม่มีนโยบาย** — email + message เก็บถาวร ไม่มี retention/ช่องทางลบ/ใครอ่าน → ฟอร์มเป็นหลุมดำ
5. **Overclaim** — "ทำเว็บมาหลายปี" ไม่มีหลักฐาน · github/linkedin ว่าง · email demo = ติดต่อไม่ได้จริง
6. **Do not show ติดไปกับ image** — Dockerfile `COPY docs` → PROFILE (รวม Brainstorm/DEBATE) อยู่ใน image
7. **Parser เปราะ** — เปลี่ยนชื่อหัวข้อ → ตก FALLBACK เงียบ ๆ · แก้ L2 แล้วอาจดึง `###` ใต้ Brainstorm หลุดขึ้นเว็บ

ตัด/แก้ Must: ฟอร์ม "ใช้ได้แม้ 501" ขัดกันเอง → Nice · "แสดง email เสมอ" ต้องเป็นอีเมลจริง · Interests "ทำไม" → Nice · Guestbook ห้าม Must · Lighthouse ต้องมีวันที่/เงื่อนไข

### รอบ 2

- **ท้า Brand:** "กำลังทดลอง" ใน tagline = ยังไม่มีผลงาน ทำให้ "รับช่วงต่อได้" จางลง → ย้ายไป Bio ย่อหน้า 2 · Lighthouse ของเว็บ 5 หน้าไม่พิสูจน์งานจริง ใช้ได้เป็นหลักฐานเสริมพร้อมวันที่/อุปกรณ์/หน้า
- **ท้า UX:** ชิป `?topic=` = dropdown + อ่าน query + validate + ส่ง API เพิ่ม → Nice (ถ้าอยากได้ ใช้ `mailto:` ที่ใส่ subject ไว้) · ข้อความ 501 ที่ชี้ไป `demo@example.com` แย่กว่า error · "ตอบภายในไม่กี่วัน" = คำสัญญาที่ไม่มีใครรับปาก (ข้อความลง SQLite ไม่มีแจ้งเตือน) → ตัด
- **ยอม:** headline "ทีมรับช่วงต่อได้" · CTA เดียว · nav 4 ข้อ · ซ่อนฟิลด์ว่าง · Interests "ทำไม" ได้ถ้าไม่แก้ type
- **3 เงื่อนไขก่อน ship (ไม่ต่อรอง):** (1) ช่องทางติดต่อจริง ไม่มี demo/ลิงก์ว่าง (2) ห้ามโชว์ `err.message` · 501/500 ใช้ข้อความคงที่ (3) Guestbook ไม่เปิดสาธารณะจนมี escape + จำกัดความยาวฝั่ง server + กันสแปม
- **แยกงาน:** Lab 04 (frontend) = L2 parser (กัน `###` Brainstorm หลุด) · contact แสดง error ปลอดภัย · guestbook `innerHTML` → `textContent` · ซ่อนฟิลด์ว่าง · Lab 05 (OpenCode) = rate limit/honeypot · ความยาวฝั่ง server · LIMIT ใน GET · API ไม่คืน `err.message` · retention · คอลัมน์ moderate · Lab 08 = Dockerfile copy เฉพาะไฟล์ที่ใช้
